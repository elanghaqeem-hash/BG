## Immediate P0 remediation package

- **Regression detected:** Draft PR #10's `cloudflare/service.ts` predates the privacy controls in `main`. Without correction, Principal can download bank-only documents by known UUID, and admin roles can see full internal workflow data.
- **Remediated on this branch:** Port `main`'s explicit Principal/Broker read scope and bank-document role allowlist into the UAT feature branch, without dropping project metadata or document `media_type` support. Config checker document upload is now forbidden. Security regression tests from `main` are restored, with an extra negative authenticated API test.
- **Release policy:** Do not merge draft PR #10 before this hardening is integrated, CI is green at resulting head, and actual five-actor privacy UAT is performed.

## Critical operational limitations

1. Regulatory text/policies in uploaded bank documents are internal legacy references. Current legal status, authority and PKS must be validated with Bank Legal, Compliance, Risk and DPS before production parameter activation.
2. The source states BG classes, claim deadlines and collateral requirements, but values must **not** be copied into production rules without determining transaction type, applicable regime and PKS priority. See the document traceability register and policy-conflict register.
3. No live SLIK, payment, core banking, registered signature, insurer certificate or regulator export has been verified.
4. Cloudflare Free is retained; quota/backup/storage/RPO/RTO proof and tenant isolation architecture are mandatory before production.
